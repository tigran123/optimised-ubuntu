# --- The same paths again, as this machine's ROOT filesystem sees them -------
# rsync is handed the source's root filesystem RAW: mounted read-only, with none
# of its bind mounts replayed. Here /home/tigran is a bind of /data/tigran (the
# DATA partition, which rsync -x never enters, so every plain /home/tigran/...
# rule above copies nothing -- which is not the same as costing nothing: /data
# is on the disk being installed, so its fstab entry and this bind survive, and
# the booted clone reads the same home directory through them; what makes the
# clone impersonal is the rules below) -- but .cache, .config, .local, .ssh,
# .nv and .cupy are bound in from /var/local/tigran-state/, which IS on the root
# filesystem and IS copied. Under their home-relative names those rules match
# nothing, so without the lines below an "impersonal" clone would carry the SSH
# private keys and the whole Chrome profile. install.sh reports any rule in this
# position before the confirmation gate.
# The home-relative rules above are kept on purpose: they are the correct ones
# for a source with an ordinary home directory, such as the reference .img.
